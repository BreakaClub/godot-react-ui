# Motion engine and extension boundaries

The renderer keeps React's authored state separate from the values currently being displayed. A React update sends a target once; the native owner advances motion on its Godot process clock. The Web build uses the same Rust code in a Wasm side module. UI work remains on the Godot main thread; this is not a background-thread performance claim.

## Ownership and data flow

1. `src/types.ts` defines typed authoring properties. `src/styles.ts` compiles the documented utility subset and inline styles into ordered style layers (breakpoint and pseudo-state conditions, shorthands expanded), with the layout, text, paint, transform and transition classes parsed by `src/utilities/` (a class Tailwind has and this build cannot honour throws a message that names the alternative, `src/utilities/hints.ts`); typed inline styles can also declare transitions, and the `transition`, `duration-*`, `delay-*` and `ease-*` classes set `transitionParts`, which native merges per field across layers.
2. `src/renderer.ts` is a persistent-mode React host. Its commit walk (`src/commit.ts`) finds changed nodes by instance identity and sends one validated `commit(layer, payload)` per layer with only the created nodes, prop diffs and changed child lists. It does not render animation frames through React, and hover, focus, press and breakpoint changes never reach it.
3. `native/props.rs`, `native/commit.rs` and `native/diff.rs` hold the typed props, validate the whole payload before anything changes, and plan the mounting transaction. `native/computed_style.rs` resolves each node's computed style (inheritance, layers, pseudo-states, breakpoints) and restyles only the nodes whose inputs changed. A target such as `height: auto` stays in the computed style; it is not overwritten with sampled pixel values.
4. `native/style_engine.rs` owns a retained Blitz document, mirrored incrementally by tag (a node's style is written to it only while the node has, or has just lost, a `transition`), and calls its public Stylo style pass. Stylo supplies interpolation, easing, delays, and reversal behavior. This adapter does not call Blitz's Parley layout/painting pipeline. Filter transitions go through the same path: a node's `filter` and `backdropFilter` lists are mirrored into the document as CSS text, Stylo interpolates them function by function (a missing function from its identity), and `style_engine::sampled_filters` reads the sampled lists back as CSS text. Stylo's `backdrop-filter` is behind a static preference that is off by default, which `style_engine.rs` turns on at runtime (`stylo_static_prefs` is a direct dependency at the same revision as Stylo). Native does no interpolation of filter values itself. Text colour, border colour, `transform` and `box-shadow` go through the same document: a transform is mirrored as CSS text and Stylo interpolates it function by function for matching lists and by decomposing the matrices otherwise (an `InterpolateMatrix` that needs the element's box is resolved in `native/transform.rs` with Stylo's own `Matrix3D::animate`), a box-shadow list layer by layer with a missing layer from a transparent one, and the sampled value comes back in `SampledStyle`. A node with a `starting:` style is given that style first and its resting style on top, so it transitions in from it.
5. `native/motion.rs` classifies a style change into transitions and intrinsic tracks, applies sampled presentation values (only for nodes whose computed style has a `transition`) to Taffy and the paint resources, and ticks on the process clock. The sampled width, height, opacity and background colour take the usual path (layout, a transform or modulate, a re-record). A sampled filter list does not: `native/filter_render.rs` turns it into material parameters of the element's backdrop or filter-group item (`material_set_param`), so a filter transition causes no commit, layout or re-record, and the transition records report the lists as CSS text. A sampled transform is evaluated against the element's current box each frame (`native/transform_state.rs`) and moves the box item, again with no commit, layout or re-record, and its transition records carry the six numbers of the matrix; text colour and border colour are sampled like background colour, and descendants whose computed colour is the ancestor's paint its sampled colour while it moves. A sampled `box-shadow` list bakes the coverage masks of the layers that changed (once per key, shared between boxes), which was not measured in the engine. `native/layout.rs` runs Taffy with text measured by Godot, `native/mount.rs` owns the mounted tree, geometry and hit testing, and `native/lib.rs` owns the root control and its input.
6. `native/render_tree.rs` owns the retained CanvasItem hierarchy: a box item and a clipping content item per element (plus scroll, overlay, text and caret items where an element needs them), a transform per move, a modulate per opacity change, and selective re-recording. An element with a `backdropFilter` or `filter` also owns effect items (a render-target copy and a draw item for the backdrop; a canvas group in a shell item for the filter) that `native/filter_render.rs` creates only while the filter exists and keeps current, with `native/blur.rs` planning a blur over the render target's mip chain. Rectangular clip intersections are used for both draw commands and hit testing. An element with a transform gives its box item `location x matrix` and everything below follows, so a transform change is one item transform; hit testing and every reader of geometry go through the matrix (`native/PROTOCOL.md`, "Transforms"). A plain box is one `StyleBoxFlat` call; shadows, rings, outlines and border sides are baked coverage masks drawn as tinted nine-patches, gradients and every box under a map that is more than a move are meshes with a feather per axis (`native/box_mesh.rs`), and a `Text` with spans is drawn per glyph over one shaped paragraph (`native/text_span.rs`, `native/text_paragraph.rs`), with no per-element material anywhere. There is still one owning Godot Control, rather than a Control for each React element.

The native owner pauses its clock while outside the scene tree and resumes when the same control reenters. Removing a node releases its layout, animation, and render resources. In `native/style_engine.rs`, removed Blitz DOM nodes are detached with `remove_node` (clearing `IS_IN_DOCUMENT` so Stylo cancels their transitions immediately) rather than freeing their `SlotMap` slot (`remove_and_drop_node`): `blitz-dom` casts `NodeId(u64)` to 32-bit `OpaqueNode(usize)` on `wasm32`, and `slotmap::KeyData::from_ffi` reconstructs truncated upper-32-bit generations as `v1`, so keeping allocated slots at `v1` preserves lossless 32-bit `OpaqueNode` lookup across unmounts and remounts. Input events reach JS through the `eventsReady` signal, emitted from inside `gui_input`; godot-rust re-borrows the root through `base_mut()` for the emission, so JS may call back into the same root (including `commit`) while native waits (`native/PROTOCOL.md`, "Input events"). Events native produces outside an input callback are queued for the next emission or the owner's per-frame `dispatchEvents()`.

## Intrinsic dimensions

Pinned Stylo handles numeric transitions but does not smoothly interpolate a numeric size and `auto`; the isolated experiment records this explicitly. The native extension therefore supplies intrinsic endpoints when `interpolateSize: 'allow-keywords'` is enabled.

A separate Taffy measurement tree uses duplicated Godot shaping resources. It resolves the target under the current parent constraints without changing the displayed tree or its text paragraphs. Pixel endpoints are passed into Stylo while the canonical model keeps the authored dimension. Each intrinsic axis releases its override when its full-precision sampled pixel value reaches the endpoint. Returning to `auto` does not wait for an unrelated paint animation to end.

During an active intrinsic transition, content, font metrics, parent dimensions, and the shell's width can invalidate the endpoint. Retargeting starts from the current presentation. Once intrinsic motion finishes, `auto` resumes normal layout behavior; content changes alone do not invent a new transition.

The prototype explicitly rejects intrinsic transitions on a flex main axis unless `flexGrow` and `flexShrink` are zero. A commit that would cause one is rejected before it is mounted: the dry-run restyle resolves the computed styles the commit would produce and checks every transitioning node. A change native itself causes (a hover, focus or breakpoint style) cannot be rejected, so it is applied without animation and logged as an error. This avoids applying flex distribution twice to an already-used intrinsic endpoint. Direct pixel/percentage transitions are also rejected: Stylo can interpolate their calc expressions, but the high-level Taffy adapter currently lacks a resolver with the current layout's containing-block context. Supporting them requires extending that layout adapter or its upstream calc callback, while retaining the same React, protocol, and native-owner boundaries. Previous-frame rectangles are not used as a substitute for CSS sizing semantics.

## Adding features

| Feature category | Extension points | Existing parts that remain responsible |
| --- | --- | --- |
| Another animated paint property | Typed protocol value, Stylo property mapping, sampled value, Godot paint adapter | React reconciliation, native clock, CSS timing and reversal |
| Another layout property | Typed protocol and Taffy mapping; computed-value resolution when required | Native measurement, layout invalidation, sibling flow |
| Stylesheets and selectors | Public stylesheet registration plus class/attribute mutations into the retained Blitz document | Stylo's selector/cascade engine; current utility resolver is not a CSS compiler |
| Rounded clipping or masks | Native clip representation and render adapter, matching hit geometry | Native ownership, transition samples, layout tree |
| Virtualization | Visible-content management over the owned scroll offsets | Style/motion engine and stable node identities |
| 3D transforms | A render target per element with a projective matrix, drawn by a homography shader (assessed, not built); `NodeTransform` classifies the matrix and exposes it for that | The matrix path through every geometry reader, Stylo's interpolation, native ownership |

Scrolling, text input, text selection and accessibility were added as such subsystems (`native/scroll_input.rs`, `native/text_input_godot/`, `native/selection_input.rs`, `native/accessibility.rs`), filters as one more animated paint property with its own render adapter, rich text as a run model beside the text engine (`native/text_span.rs`, `native/text_decoration.rs`, flattened in the renderer's host config so a nested `Text` is never a node), transforms as a map every reader of geometry goes through (`native/transform.rs`, `native/transform_state.rs`), and box shadows, rings, outlines and gradients as animated paint with baked masks and meshes (`native/shadow_mask.rs`, `native/box_mesh.rs`, `native/gradient.rs`). The remaining categories require new subsystems, not just additional utility names. The architecture provides ownership boundaries; it does not claim those features are implemented or costless. The current transition property set is width, height, opacity, background color, text color, border color, `filter`, `backdropFilter`, `transform` and `boxShadow` (`TransitionProperty::ANIMATABLE`, which `transition-all` animates; anything else jumps). General keyframes, animation lifecycle callbacks, full CSS stylesheet authoring, and browser-complete layout behavior are not claimed.

## Measurement contract

Profiling is opt-in and bounded. JS samples record the commit walk, JSON encoding, synchronous native `commit` call, and complete commit durations. A reconciliation window includes its nested host/native work and must not be added to those stages again. Payload size is reported as UTF-16 characters, not as wire bytes.

Native samples separate commit parsing, validation and planning, mounting, layout, geometry, motion work, and paint (canvas-item re-record) CPU work. The activity counters also report filter effects (items, materials and shaders made and freed, material and copy-rectangle updates, subtree walks), which stay zero in a tree without filters. `animating` reports actual engine/owned intrinsic activity; the transition records are diagnostics rather than Stylo's private per-property state. Rounded color or geometry values are not used as the root's completion signal.

The browser verifier records RAF intervals, input/render-request to observed-draw RAF latency, and JS heap observations. None of these measures physical display latency or GPU execution time. Screenshots and full tree snapshots are kept outside the timed benchmark windows. The synthetic matrix updates every keyed cell at 50, 500, and 2,000 cells, with both plain boxes and shaped text; offscreen nodes are not virtualized. It is a scaling probe, not a claim that those workloads represent a game HUD.

See `native/PROTOCOL.md` for the exact wire and diagnostic schemas and the generated files under `artifacts/motion-web-verification/` for measurements from a specific build.
