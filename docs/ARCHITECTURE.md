# Architecture and performance boundary

React 19.2.0 is the supported version; `react-reconciler` 0.33.0 is pinned to its compatible peer contract. React is a peer dependency so the application and renderer share one instance. Native dependencies are `godot` 0.5.5, Taffy 0.15.0 (git revision `fca167c`), and `blitz-dom` 0.3.0-beta.4 (git revision `3f85506`, retaining Stylo 0.23.0 for CSS transition resolution), locked by Cargo. The native builds are bound to the Godot 4.7.2 API (`native/api/stock-4.7.2`) and loaded by Breaka's 4.8 as well as by stock 4.7.2; the `breaka` profile's Web build is bound to the exact API exported from the project's Godot 4.8 binary and the `stock` profile's Web build to the 4.7.2 one, all recorded in [native/api](../native/api/README.md). The demo's bundles contain the production builds of React and `react-reconciler`; the renderer registers with the React DevTools hook (as production bundle type 0) when a page installed one, and the demo's code editor keeps component state across an edit through stable family proxy components instead of `react-refresh/runtime`.

The architecture is React Native Fabric's, end to end. The reconciler runs in persistent mode: during render it creates and clones lightweight, immutable JavaScript instances that share unchanged children, and it makes no native call, so abandoned concurrent renders cost nothing natively. At commit, a pure walk (`src/commit.ts`) finds the changed nodes by instance identity (an instance identical to its committed one skips its whole subtree) and sends **one `commit(layer, payload)` call** carrying only the created nodes, the prop diffs and the changed child lists. Native validates the whole payload before changing anything, diffs each changed child list (longest increasing subsequence for moves) into a mounting transaction, applies it to a mounted tree keyed by `u32` tags that JS allocates, resolves computed styles for the nodes whose inputs changed, lays out with Taffy's retained tree, updates geometry only where it changed, and re-records only the canvas items whose visuals changed. Event closures stay in JS, while native input queues are drained outside mutable Rust calls. The persistent shadow tree lives in JS rather than behind native handles because GodotJS cannot make V8 account for native memory behind wrappers.

Taffy owns Flexbox/Grid geometry. Godot `TextParagraph` owns text shaping and intrinsic measurement. Stylo (via `blitz-dom`) owns transition and keyframe animation timing, easing, interruption, and reversal on the native process clock, while a dedicated native measurement tree supplies intrinsic endpoints when `interpolateSize: 'allow-keywords'` is active. A single custom `Control` owns a retained hierarchy of lightweight `RenderingServer` `CanvasItem` RIDs that mirrors the view tree (a box item and a clipping content item per element), with rectangular clipping (`overflow: 'hidden'`), rounded where the padding box has rounded corners (a `CLIP_ONLY` canvas group), for both rendering and hit testing; there is no Godot `Container` or `Control` for every React element. Moving an element changes one transform, an opacity change one modulate, and only an element whose own visuals or size changed re-records. A box's fill, its border, its shadows, rings and outline are baked coverage masks drawn as tinted nine-patches, shared between boxes of the same shape and packed into shared atlas pages (a square fill or border is stretched from the atlas's white texels), so consecutive boxes are one draw call: a `StyleBoxFlat` was a polygon, which the engine never batches. Gradients are meshes over a baked one-pixel ramp, and a box under a transform is a feathered mesh (no per-element material anywhere: materials break batching, and the Compatibility renderer on the Web draws nothing past 16 per-instance shader parameters). An element's text is in an item of its own, and where no box drawn after it overlaps it, it is drawn after the boxes of its sequence (the elements under one clip, scroll offset, opacity, transform or filter), so a list's rows are one draw call for their boxes and one for their text (`native/text_layers.rs`). A `Text` with nested `Text` is one node whose spans are flattened in the renderer's host config (`src/rich-text.ts`) and drawn per glyph over one shaped paragraph. Each `<Portal>` has its own container in the overlay layer. Paint and layout invalidation are separate. The engine culls canvas items against the viewport only, so an element whose painting (its own, with its shadows, outline and text, and everything painted under it) lies wholly outside the clips of its paint ancestors has its items hidden (`native/clip_cull.rs`, `stacking::clip_culled`): the rows of a list scrolled out of view cost no draw call. The pass runs once a frame from the rendering server's `frame_pre_draw`, and only after something it reads changed; an element under a `filter` or `backdrop-filter` is never culled, nor is what it is painted under. Measured natively on the Scrolling lab at 402 × 678 (stock 4.7.2, Compatibility), draw calls per frame: idle 76 before these three changes, 73 with the culling, 52 with the atlas, 27 with the texts after the boxes; the busiest frame of a wheel scroll 181, 111, 73, 43; at rest after it 92, 63, 45, 23. The culling and the texts' order draw byte-identical frames; the atlas changes only the antialiasing of rounded corners, now exact coverage, by up to 32 levels in a channel. The atlas pages are 1024 × 1024 RGBA8, 4 MiB in memory and 4 MiB as a texture each; the HUD lab's boxes are in one (the paint verifier's cost check holds a page of plain boxes to one). Snapshots and opt-in profiles expose node geometry, computed styles, active transitions, commit counters (`nodesCreated`, `nodesUpdated`, `mutations`, `boxRecords`, `contentRecords`), and commit, layout, paint, and stage timing counters.

Measured on Chrome 156 (debug template, development React, which is from before the demo bundled production React; a heavily swapped Mac; `node scripts/verify-motion-web.mjs --acceptance`): changing one cell's colour costs the native `commit` 0.17 to 0.20 ms at 50 and at 2,000 cells (the previous renderer: 0.79 ms and 11.7 ms), with one mutation and a 216-character payload at both sizes. Hovering and resizing across a breakpoint cause no React commit and no commit call; a 200-move hover sweep over 2,000 cells re-records two boxes per move. Updating all 2,000 cells takes about 52 ms (previously 57 ms of reconcile plus draw) and an idle frame records nothing. React still walks a parent's children when one child changes, so one change under a flat parent of 2,000 siblings costs 18 ms of JavaScript (4 ms with memoized cells) against 1.8 ms when the same cells are grouped in rows of 50; group large lists.

Costs that remain: the commit payload is one JSON string per commit, a parent of many siblings is still copied by React when one child changes, intrinsic-size transitions clone the Taffy tree to measure an endpoint, and Taffy rounds its whole layout after each layout pass. It does not claim zero allocation or a frame-rate guarantee. Custom GodotJS/V8 hooks are intentionally deferred until measurements identify a bridge bottleneck; GodotJS already supplies the scheduler and ClassDB facilities required here.
