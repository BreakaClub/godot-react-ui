# Native protocol v1

`ReactUiRoot` is a Godot `Control`; GodotJS imports it from `godot` and calls the camelCase methods `applyBatch`, `getSnapshot`, and `drainEvents`. All methods run on the Godot main thread. There are no synchronous JS callbacks from native mutable methods.

`apply_batch(json: String) -> String` accepts a JSON array of tagged commands. Empty return means success; a nonempty return describes validation failure. IDs are explicit unsigned 32-bit integers; ID 0 is the permanent viewport root. IDs must not be reused during a root's lifetime. A batch validates against a staged metadata tree before native state is changed.

```json
[
  {"op":"create","id":1,"kind":"view"},
  {"op":"style","id":1,"style":{"display":"flex","flexDirection":"column","width":"100%","padding":24,"gap":12,"backgroundColor":"#111827"}},
  {"op":"create","id":2,"kind":"text"},
  {"op":"text","id":2,"text":"Hello React"},
  {"op":"children","id":1,"children":[2]},
  {"op":"children","id":0,"children":[1]}
]
```

Commands: `create {id,kind:"view"|"text"|"button"}`, `style {id,style}`, `text {id,text}`, `children {id,children:number[]}`, `remove {id}`. `style` replaces the complete resolved style; omitted properties reset to defaults. `children` replaces ordered children and permits reparenting; cycles, duplicate children, missing IDs, and root removal are errors. `remove` removes a node and its descendants. Only mounted nodes draw, receive events, or participate in viewport layout.

Style properties (camelCase): width/height/minWidth/minHeight/maxWidth/maxHeight/flexBasis accept nonnegative numbers, `"auto"`, or percentage strings; display `flex|grid|none`; flexDirection `row|column|row-reverse|column-reverse`; flexWrap `nowrap|wrap|wrap-reverse`; flexGrow/flexShrink nonnegative numbers; gap/rowGap/columnGap, padding/paddingTop/paddingRight/paddingBottom/paddingLeft, margin/marginTop/marginRight/marginBottom/marginLeft numeric pixels; alignItems/alignSelf `start|end|center|stretch|baseline|flex-start|flex-end`; justifyContent `start|end|center|space-between|space-around|space-evenly|flex-start|flex-end`; gridTemplateColumns positive integer (equal fractional columns); backgroundColor/color/borderColor `#RGB|#RGBA|#RRGGBB|#RRGGBBAA`; fontSize positive integer; borderRadius/borderWidth nonnegative pixels; opacity 0..1; disabled boolean; textAlign `left|center|right`. Unsupported properties fail explicitly. Default is flex column, transparent background, white 16px text, no spacing, normal flex shrinking. Text is shaped and wrapped with Godot TextParagraph; no JS text measurement callback.

`get_snapshot() -> String` returns JSON `{nodes:[{id,kind,text,parent,children,rect:{x,y,width,height},style}],stats:{layoutPasses,batches,nodeCount,paintPasses,layoutMicros},width,height,hovered,focused,pressed}`. Rectangles use root-local logical pixels. Detached nodes have zero rectangles. Root ID 0 appears in nodes; nodeCount excludes it.

`drain_events() -> String` returns and clears JSON events `[{id,type,x,y}]`; event types are `pointerdown|pointerup|pointermove|pointerenter|pointerleave|click|focus|blur`. Coordinates are root-local. Native hit testing chooses the topmost mounted visible element in reverse paint order; JS handles propagation. Enabled buttons participate in Tab/Shift-Tab focus and Enter/Space activation. Pointer events retain their deepest hit element IDs. A click targets that element when press and release hit the same enabled element; when their deepest hits differ but share the same enabled button ancestor (for example button padding and its label), the click targets that button. Crossing to another button or releasing outside the pressed button does not activate it. Disabled buttons and descendants of disabled ancestors cannot activate. The root clips drawing and input to its own rectangle.

Prototype limits: no scrolling, text input/IME, accessibility tree, images, rich inline text, full rounded clipping, a public CSS stylesheet/selector API, arbitrary keyframe animations, or custom native materials. Flex/grid and text shaping are native; styles arrive resolved from the JS renderer. Text color and font size are resolved per element; inheritance belongs to the JS style layer. Native drawing uses owned CanvasItem RIDs with cached resources and one Control for the whole React tree.

## Native CSS motion and clipping

Resolved styles can include `transition: {properties: ('width'|'height'|'opacity'|'backgroundColor')[], durationMs: number, delayMs?: number, easing?: 'linear'|'ease'|'ease-in'|'ease-out'|'ease-in-out'}`. Duration and delay are finite nonnegative milliseconds. Easing defaults to CSS `ease`. A retained Blitz/Stylo style tree owns numeric/color interpolation, delay and reversal shortening. One root-owned Godot process clock advances it; no JS animation frames or per-frame mutation batches are required. The clock pauses when the root leaves the scene tree and resumes when the same root reenters.

`interpolateSize: 'allow-keywords'` opts into native intrinsic dimension endpoints; it is inherited, with `numeric-only` the default. Canonical authored `auto`/percentage values remain in the model. A separate Taffy probe with duplicated Godot text-shaping resources resolves endpoints without modifying visible geometry. Explicit pixel endpoints are supplied to Stylo while moving, and authored dimensions are restored without retriggering animation when that axis’s full-precision sampled pixel value exactly reaches its target, independently of unrelated paint transitions. During an active intrinsic transition, content/font changes, parent size changes, and changing shell width remeasure and retarget from the currently sampled value. Settled `auto` remains ordinary intrinsic layout.

Intrinsic animation on a flex main axis requires `flexGrow: 0` and `flexShrink: 0`; otherwise the batch is rejected rather than applying flex distribution twice to an already-used endpoint. Same-unit pixel or percentage transitions are supported. Direct pixel-to-percentage or percentage-to-pixel transitions are explicitly rejected: Stylo can sample their `calc()` values, but the selected high-level Taffy tree has no current-layout calc resolver. This prototype does not approximate that containing block with stale previous-frame geometry.

`overflow: 'hidden'` clips descendants and text to the sampled padding box, with ancestor intersections; the border is still painted. Drawing uses owned native CanvasItem RIDs, while scene ownership remains one Control. Hit testing and focus eligibility use the same clip geometry. This is rectangular scissor clipping: border radius affects paint, not the clip shape. Nested rounded masks are not claimed.

Snapshots add `clockMs`, `transitions: [{id,property,current,target,startedAtMs,durationMs}]`, and per-node `presentation: {width,height,widthIsAuto,heightIsAuto,opacity,backgroundColor}` plus `clipRect: {x,y,width,height}|null`. Dimension/opacity diagnostics are numbers and colors are hexadecimal RGBA strings. The `widthIsAuto` and `heightIsAuto` flags read the actual Taffy presentation style, not just authored metadata. Transition records are native tracking diagnostics, not access to Stylo's private per-property animation table; they remain conservatively until global CSS activity finishes. `durationMs` is the configured duration, while Stylo may shorten a reversal.

`get_activity() -> String` provides compact JSON `{batches,layoutPasses,paintPasses,animationFrames,animating,trackedTransitions,clockMs,drawSerial,nodeCount}`. `animating` reflects actual global Stylo activity or owned intrinsic transitions; use it for completion, rather than the number of tracked records. `set_profiling(enabled: bool)` controls an off-by-default 512-sample ring; `take_profile() -> String` drains `{samples,dropped,counters}`. Samples have `kind: 'batch'|'frame'|'draw'`; batch records parse/clone/validate/sync/layout/geometry/total microseconds, frame records style/measure/layout/geometry/animation microseconds, and draw records CPU microseconds. Nested layout/geometry timings are subtracted from their surrounding bookkeeping phases. Draw timing measures CPU command/shaping work, not GPU completion. Profiling drops the oldest sample at capacity and reports how many were dropped.
