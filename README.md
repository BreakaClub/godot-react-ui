# godot-react-ui

A standalone prototype of React TSX in GodotJS, with Rust/Taffy layout and native Godot drawing. It is not integrated into `breaka-rpg`.

One repository contains the GDExtension, the `godot-react-ui` TypeScript package, and an interactive Godot demo. Keeping them together lets the native protocol and renderer evolve together while the boundary is experimental. The package is marked `private: true`; it has not been published. Repository creation and local builds do not create a remote, push, or deploy anything.

## Run the native demo

The current native addon manifest targets Apple Silicon macOS. Use the Godot 4.8 V8/GodotJS build, Node.js, pnpm 11.5.2, and rustup. `rust-toolchain.toml` pins Rust 1.99.1. The build uses rustup's Cargo, avoiding this workstation's unrelated Homebrew Rust installation.

```sh
export GODOT=/Applications/Godot48.app/Contents/MacOS/Godot
pnpm install
pnpm build:native
pnpm build
pnpm demo
```

`build:native` compiles the optimized Rust library and installs it into `demo/addons/godot-react-ui/bin/`. `build` typechecks before bundling the demo and emitting CommonJS, ES modules and declarations into `dist/`. Both package entry points are importable; `pnpm pack` creates a local npm tarball without publishing. Generated GodotJS declarations and scene wrappers are included under `demo/typings/` and `demo/gen/`; `.uid` files are project metadata. Compiled libraries, JavaScript bundles, and the `.godot` import cache are generated locally.

The demo has four tabs:

- **Counter:** real React state, derived values, closures, effects, context, disabled buttons, pointer states, and keyboard activation.
- **Inventory:** a responsive Taffy grid, keyed component state, reordering, filtering, insertion/removal, and an empty state.
- **Interaction:** the event pipeline: capture and bubble with `stopPropagation()`, `preventDefault()` that stops native's focus default action, synchronous dispatch (a handler observes native state before its default action runs), `pointerenter`/`pointerleave` that reach only the elements crossed, and handlers that remove their own target, detach the root from the scene tree, or unmount it while native is still inside the press.
- **Motion:** native Blitz/Stylo CSS transitions (`width`, `height`, `opacity`, `backgroundColor`), intrinsic `0 ↔ auto` height transitions (`interpolateSize: 'allow-keywords'`), rectangular clipping (`overflow: 'hidden'`, `'scroll'`, `'auto'`) for both rendering and hit testing, in-flight retargeting across text/font/width/viewport changes, rapid reversal, tree detach/reattach pause/resume, and active-transition removal.

Resize the window to see `md:` classes recompose the layout. Tab and Shift-Tab move between enabled buttons; Enter and Space activate them. All provided Godot launch scripts use `--audio-driver Dummy`.

The demo owner also puts a full-window Godot `ColorRect` behind the React root and counts what reaches it and `_unhandled_input`. The verifiers render pages through `godotReactDemo.showLab(name)`: a HUD over it (`'hud'`: every ancestor is `pointer-events-none`, a few controls are `pointer-events-auto`) to prove that empty space, keys the UI did not use, and wheel ticks it did not consume belong to the game.

### Engine profiles: `breaka` (default) and `stock`

Every build, run and verify script takes the same selector, and `breaka` (Breaka's custom Godot 4.8 with its GodotJS) is the default:

```sh
pnpm verify                          # breaka: /Applications/Godot48.app, API dumps in native/api, target/, artifacts/
pnpm verify --engine=stock           # stock Godot 4.7.2 + upstream GodotJS
GODOT_REACT_ENGINE=stock pnpm verify
```

`--engine=<name>` wins over `GODOT_REACT_ENGINE`; an unknown name is an error. `stock` defaults `GODOT` to `/Users/ben/Development/godot-stock/bin/godot-stock` (a wrapper that redirects `HOME`, so a run cannot write to the user's Godot folders; see that tree's `BUILD_NOTES.md`). `GODOT` still overrides either profile's binary, and its `--version` must match the profile. Each profile binds the Rust extension to its own API dumps (`native/api` for `breaka`, `native/api/stock-4.7.2` for `stock`), builds in its own target directory (`target/` and `target/stock`; Web `target/web` and `target/stock-web`), writes evidence under `artifacts/` and `artifacts/stock/`, and typechecks against its own GodotJS declarations. Both install the library where the one checked-in `react_ui.gdextension` expects it, and the installed library records which profile built it: a run refuses the other profile's library, so build first (`pnpm build:native --engine=stock`). Finish with `pnpm build:native` to leave the default installed. On Web the `stock` profile uses Emscripten 4.0.11 and the stock templates (debug and `--release`; [docs/WEB.md](docs/WEB.md) has the commands). Details and decisions: [docs/tracks/stock-engine.md](docs/tracks/stock-engine.md).

### Installed builds are checked against the source

A build records what it was made from: a SHA-256 of the contents (never the modification times) of `native/` (without its API dumps and Markdown), `Cargo.toml`, `Cargo.lock`, `rust-toolchain.toml`, `.cargo/config.toml` and `build.rs` if present, and the profile's API dump pair, plus the cargo features it was built with. It is written into the stamp beside each installed build (`react_ui.build.json`, `react_ui.web.build.json`, with the engine profile, probe flag and library hash they already held), beside cargo's own output in the target directory, and into a Web export's `build-receipt.json` (`extension`). Every script that runs or serves a build compares that with the working tree first and refuses, naming the files that differ and the command that rebuilds: the native verifiers, `pnpm demo`, `pnpm dev` (at startup), `pnpm gen:types`, the Web verifiers and `pnpm demo:web`, the Web export, and `pnpm test:types --engine=stock`, which checks the stock library its typings are generated from and never builds it. The refusal comes before any window or browser opens. A probe build is never fresh for a default run, nor a `--faults` build (a feature set of its own). A Web export's receipt also records a digest of the TypeScript, demo and script sources it was bundled from, the engine template, and each exported file's size and hash; the guard checks all of it, and the fix it names for those problems is `pnpm build:web --export-only`. What the guard does not cover: the Rust and Emscripten toolchains beyond `rust-toolchain.toml`, the engine itself, the compiled JavaScript, and the tracked `demo/typings`; a hand-run `cargo build` changes the library under a stamp that does not describe it (the next `build:native` cleans and rebuilds); and godot-rust's generated bindings follow cargo's own tracking of the API dump's mtime, so a dump restored with an old mtime would not rebuild them (do not edit a dump by hand).

`build:native` and `build:web` do not rely on cargo's own check, which compares modification times and so keeps an artifact when a source is restored to older content with its old mtime. Unless the target directory's stamp says its artifact is a build of exactly the current sources, they run `cargo clean -p godot-react-ui` first (this crate only; the dependencies stay cached). The first build after the guard was added therefore recompiles the crate once. Decisions and limits: [docs/tracks/freshness.md](docs/tracks/freshness.md).

For TypeScript iteration, run `pnpm dev`. It watches the demo bundle and opens the Godot editor; run the demo there and restart its scene when changing initialization. Native extension changes require rebuilding and restarting Godot because extension hot reload is disabled. `pnpm dev` refuses to start on a library that is not a build of the current sources; it does not check again while it runs.

### What a PASSED line means

Each native verify script prints a summary after its windows. Read it, not just the exit code (docs/tracks/verifier-integrity.md):

- `landscape: PASSED` is a run that passed on its first launch. `PASSED (PARTIAL: not run: pointers, drag, …)` is a run that left sections out (`--only=…`; a plain `verify:interaction` runs every default section and is not partial), or checks out (`verify:text-layout --headless` runs no pixel checks; the platform focus check of `verify:a11y` is skipped when the window is not the key window). A partial run is not the verification. `(N recorded engine gap(s), not failures: …)` lists what an engine cannot convey that a verifier recorded instead of failing; `(a disturbance reached its window, but it passed)` says something reached the window and the run passed anyway.
- `PASSED after N disturbed failure(s). First failure: …` is a run that failed, was disturbed by something that reached the window (a real mouse event, a focus loss with a press in flight) shortly before it failed, and passed on a re-run. Its first log and captures are kept (`run-attempt-1.log`, `<window>-failed-attempt-1/`). A failure with no such disturbance is real and is not re-run. `--no-retry` runs each window once: use it for negative controls, where a re-run would hide the failure you are looking for.
- Every window is also refused if the installed library stopped matching the sources since the script started.

A verifier run keeps its own clipboard and never touches the Mac's: native runs hold it in the process's memory (`ReactUiRoot.isolateClipboard(true)`), and `verify:interaction:web` replaces `navigator.clipboard` with an object in the page's memory (no permission is requested). Whether headless Chrome would have reached the system pasteboard, and the engine's own last step onto the Mac's pasteboard, were not measured, because measuring writes to it.

## Editing TypeScript: use an external editor

Godot's script editor does not understand TypeScript. If a `.ts` or `.tsx` file is open in it when the editor saves, it rewrites the file (tabs for the indentation it thinks is wrong: `demo/src/main.ts` came out with 254 changed lines). The scripts that launch an editor (`gen:types`, the import step of `pnpm demo` and every native verifier, the stock typings, `pnpm dev`) take TypeScript out of the project's saved editor layout first (`build:web`'s headless export included), so none is opened by them. That cannot stop you opening a `.ts` file by hand in the Godot editor: edit TypeScript in an external editor, and keep it closed in Godot's.

## Authoring

Use ordinary React, including hooks and component composition, with five native primitives (`View`, `Text`, `Button`, `Portal` and `TextInput`) and a small component kit built from them (`Checkbox`, `Switch`, `RadioGroup`, `Slider`, `Select`, `TextField`, `ScrollView`):

```tsx
import { useState } from 'react';
import { Button, StyleSheet, Text, View } from 'godot-react-ui';

const styles = StyleSheet.create({
  panel: { padding: 24, borderRadius: 16, backgroundColor: '#ffffff' },
});

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <View style={styles.panel} className="gap-4">
      <Text className="text-3xl text-slate-900">Count: {count}</Text>
      <View className="flex-col md:flex-row gap-3">
        <Button
          className="rounded-lg bg-indigo-600 hover:bg-indigo-700 active:bg-indigo-800 text-white px-4 py-3"
          onClick={() => setCount(value => value + 1)}
        >
          Add one
        </Button>
        <Button
          disabled={count === 0}
          className="rounded-lg bg-slate-100 text-slate-700 disabled:text-slate-400 px-4 py-3"
          onClick={() => setCount(0)}
        >
          Reset
        </Button>
      </View>
    </View>
  );
}
```

`View` defaults to a flex column. `Text` uses Godot text shaping and wrapping; as in React Native, raw strings may only appear inside `<Text>` (a raw string in a `View` throws). `Button` participates in native hit testing and keyboard focus and renders its string and number children as one `Text` label. `Portal` renders its children into the overlay layer, which always draws above the main layer and is hit-tested first. `color`, `fontSize`, `textAlign`, `pointerEvents`, `cursor`, `userSelect` and `selectionColor` inherit natively. Focus: `Button`s, and any element with `tabIndex={0}` (in the tab order) or `{-1}` (focusable only), take focus from a press, Tab (document order, wrapping, never a disabled or invisible element), `handle.focus()` or `autoFocus`. The focus ring and `focus-visible:` styles mark a keyboard focus only (Tab, or `focus()` after keyboard input); a press focuses without them. `onKeyDown`/`onKeyUp` (cancelable `keydown`) carry DOM `key`, `code`, `repeat` and the modifiers; Enter and Space press a focused `Button` and click it on release, without pointer events (a prevented `keyup` ends the press with no click), and a focus trap is a few lines of `onKeyDown`, `preventDefault()` and `focus()`. Events include `onClick`, `onDoubleClick`, `onAuxClick` (any button but the primary), `onContextMenu`, pointer enter/leave/down/up/move/cancel (each with a `Capture` variant except enter/leave and the click family beyond `onClick`), `onWheel` (cancelable; deltas are in wheel ticks, positive down and right) and focus/blur. A `click` goes to the nearest common ancestor of the press and release targets, as in browsers (two parts of one enabled button click the button; a release on a disabled element or over nothing clicks nothing). They have DOM semantics: capture handlers run outermost first, then bubble handlers from the target up, then root listeners (`root.addEventListener`); `pointerenter`/`pointerleave` do not bubble and run only for the elements the pointer crosses. Events provide `target`, `currentTarget`, `eventPhase`, root-local coordinates, `pointerId`, `pointerType`, `button`, `buttons`, modifiers, `timeStamp`, `stopPropagation()` and `preventDefault()`. A pointer press is dispatched synchronously from inside Godot's input callback, so `preventDefault()` on `onPointerDown` stops native's focus default action before it runs. Pointers: the mouse (pointer 1, every button, click counting in `detail`) and touches (pointer 2 and up, multi-touch, captured to where they went down; the engine's mouse emulation is ignored, so a touch is never also a mouse press and never hovers) produce DOM pointer events. `handle.setPointerCapture(pointerId)` (also `releasePointerCapture`, `hasPointerCapture`) routes a pressed pointer's moves, up and cancel to an element wherever it goes, including outside the root and the window; `pointercancel` ends a contact the OS, a lost window focus or a detached root interrupted. Godot co-operation: the root takes pointers only where an element can receive them, so empty space and `pointer-events: none` regions (when every ancestor is `none` too) reach the Godot `Control`s underneath and then `_unhandled_input`; `cursor-*` sets the window cursor through the root's `_get_cursor_shape`. The root takes no key focus when it enters the tree: its owner calls `grabFocus()` for keyboard-first behaviour, and an element taking focus grabs it. Tab is consumed only when it moved focus, Enter and Space only when they activated a focused button, and a wheel tick only when a handler calls `preventDefault()`; everything else reaches `_unhandled_input`. A press on something that cannot take focus hands key focus back to the game. `viewportX`/`viewportY` are canvas coordinates (what `_unhandled_input` receives), `x`/`y` are root-local. Positioning follows CSS with React Native's `zIndex`: `position` (`static`, `relative`, `absolute`, `fixed`; no `sticky`), `top`/`right`/`bottom`/`left` (pixels, percentages, `auto`; negative allowed; the `inset` shorthand and the `top-4`, `inset-0`, `inset-x-0`, `left-1/2`, `-top-2` utilities) and `zIndex` (the `z-10`, `z-[3]`, `-z-10` utilities). An `absolute` element is placed in, painted by and clipped by its nearest positioned ancestor (else the root), not by its parent: a menu in an `overflow-hidden` card stays visible where its containing block is outside the card. `zIndex` orders the elements one parent paints; there are no stacking contexts. `<Portal>` content is positioned like any other (`absolute inset-0` is a full-window backdrop); read an anchor's rectangle with `getRect()`. Events from inside a portal bubble through the overlay tree, not through the React ancestors of the `<Portal>`, and its Tab stops come after the main layer's. Scrolling: `overflow` `scroll` or `auto` on an axis makes a scroll container (the kit `ScrollView` wraps one with a content element that cannot shrink). The wheel, a trackpad pan, the keyboard (arrows, Page, Home, End, Space on the focused element's container; Tab and `focus()` scroll their element into view), a touch pan with momentum and an overlay scrollbar thumb dragged with the mouse all scroll it; a scroll the innermost container cannot take chains to the next one unless it has `overscroll-contain`, and a wheel tick nothing can take reaches `_unhandled_input`. `onScroll` (coalesced, not bubbling) and the handle's `scrollTo`, `scrollBy`, `scrollIntoView` and `getScrollState` read and move it. A touch that moves beyond 8 px pans the container unless `touch-action` forbids it, which cancels the pointer and its `click`; `touch-none` keeps the pointer events (the kit `Slider` has it). Scrolling moves one canvas item: no commit, layout, restyle or re-record happens (the snapshot's `scrollUpdates` and `overlayRecords` are what change). Text selection: `select-text` (inherited; the default is `select-none`) lets the mouse select the text of `Text` elements: a click collapses, a double click selects a word, a triple click the node's text, dragging extends (across elements, skipping `select-none` text, and to the start or end of the text after or before a pointer that is not over text) and Shift+click extends. A press on a `Button`, on an element that captured the pointer or prevented `pointerdown`, or on anything not selectable starts nothing and clears the selection. A selection takes Godot key focus for the root (no element is focused) so `ui_copy` (Cmd/Ctrl+C) puts the selected nodes' text, joined by newlines, on the clipboard and `ui_text_select_all` selects all selectable text; changing or removing text the selection covers clears it. `selection-[#hex]` colours the highlight, which is drawn under the text in the content item, so it scrolls and clips with its container; selectable text shows the text cursor. `root.addEventListener('selectionchange', ...)` (no payload, coalesced), `root.getSelection()` (the anchor and focus as element handles with UTF-16 offsets, the selected `text`, `isCollapsed`), `root.clearSelection()` and the `useTextSelection()` hook read it. Drag and drop follows HTML inside one root: `draggable` (and `dragPreview`: `native`, a translucent copy of the element that follows the pointer, or `none`) makes an element a drag source, once a mouse moves past `Viewport`'s drag threshold or a touch is held still for half a second (a touch that moves first pans instead, and a prevented or captured `pointerdown` starts nothing; text inside a draggable element starts no selection). `onDragStart` (cancelable; fills `event.dataTransfer`), `onDrag`, `onDragEnter`, `onDragLeave`, `onDragOver` (cancelable: preventing it makes the element a drop target for the `dropEffect` the handler leaves, if the source's `effectAllowed` permits it), `onDrop` (cancelable) and `onDragEnd` (`dropEffect`, root-local and viewport coordinates, and `endedOutsideRoot` for a release beyond the root) all bubble; starting a drag cancels the pointer (`pointercancel`, no `click`). `DataTransfer` has the HTML protection modes (`setData` in `dragstart` only, `getData` in `drop` only). The cursor shows can-drop or forbidden, Escape cancels, a scroll container scrolls when the pointer rests near its edge, and the target follows a scroll under a stationary pointer. Hover, press and focus are native state: they restyle `hover:`, `active:`, `focus:`, `focus-visible:`, `focus-within:` and `disabled:` variants without any React render or JS call. Refs expose a typed handle with its native tag and `getRect()` (a native query); `testID` supports inspection and `findByTestID` (a native query) without becoming native identity.

### TextInput

`TextInput` (and the kit's `TextField`) keeps its text natively and follows React Native's controlled-input protocol: pass `value` and store what `onChange` reports, or pass `defaultValue` and leave it alone. An edit is applied first and reported (`beforeinput`, then `input`); a `value` that differs from the text the user made is sent back with `setTextAndSelection`, so an `onChange` that stores something else (capitals, a filtered string, the old value) takes effect at once. Two consequences that a developer used to a plain `<input>` can trip over, and that a controlled `<input>` in a browser has too:

- **The caret goes to the end when a controlled value changes the length of an edit.** It stays where it was when the value has the length of the edit's text (a transform such as capitals) or goes back to the text from before the edit (a rejected edit, with the selection it had). Any other value, a mask that adds separators for instance, puts the caret at the end of the new text.
- **`setTextAndSelection` clears the undo history.** A controlled field whose `onChange` rewrites what was typed, or refuses some of it, has no undo for the text before the rewrite.

Also: `multiline` is fixed when the input is created (a commit that changes it is rejected); a paste with no text pastes nothing; a triple click selects all of a text area's text, not a line (`LineEdit`'s rule); a `TextInput` is always a text field to assistive technology (its `role` can only remove it from the tree); and there is no `aria-labelledby` or `aria-describedby` (native rejects unknown props), so the kit's `TextField` sets `aria-label` and `aria-description`.

### Accessibility

`role` (the ARIA names of `UIRole`) and the `aria-*` props of `UIAriaProps` (`aria-label`, `-description`, `-valuetext`, `-placeholder`, `-hidden`, `-disabled`, `-expanded`, `-selected`, `-readonly`, `-required`, `-modal`, `-checked` including `'mixed'`, `-valuemin`, `-valuemax`, `-valuenow`, `-live`, `-orientation`) reach Godot's `AccessibilityServer`. Native keeps one accessibility element per exposed node: a `Button`, a `Text` with text, a `TextInput`, a scroll container (`SCROLL_VIEW`) and anything with an explicit `role`; `aria-hidden` removes a subtree. Each has a name, role, state and bounds that follow scrolling, and actions: click, focus, a text input's selection and edits (through `beforeinput`), a slider's increment, decrement and set value (`onAccessibilityAction`; the kit `Slider` answers it), the scroll actions, and a scroll bar element for each scrollable axis. The kit sets its own roles and states. What was verified where (the macOS tree was read only on the `stock` engine profile, which has AccessKit; Breaka's engine has no accessibility driver; VoiceOver was never run by hand) is under "Current limits".

### Mounting

Mount with `createRoot(nativeSurface, { subscribeToEvents }).render(<App />)`, where `nativeSurface` is a `ReactUiRoot` from `godot`. `subscribeToEvents(listener)` is required: the owner connects a `Callable` for `listener` to the surface's `eventsReady` signal and returns a function that disconnects it (a GodotJS `Callable` holds its function strongly, so `unmount()` calls that function or the whole root would stay reachable). Native emits `eventsReady` from inside its input callbacks. The owner also sets the surface size (native restyles the nodes whose breakpoints the new width crosses, with no React render), calls `dispatchEvents()` each frame for events native queued outside an input callback, and calls `unmount()` before freeing the surface. [The demo owner](demo/src/main.ts) shows the complete lifecycle, including tree re-entry. `render()` commits the initial render synchronously; later hook updates use React's scheduler.

### Display scale

The root draws its text and its rounded edges at the font oversampling of the viewport it is in (`Viewport.get_oversampling()`), which is what Godot's own controls draw at. A `Window` carries its content scale factor, a stretch mode's scale and an oversampling override in it, so the owner decides how sharp the UI is by scaling its window; the library follows, including a change of scale that nothing else tells it about (a window moved to another display, the owner changing `contentScaleFactor`): it draws again at the new scale without a commit. `Window.use_font_oversampling = false` (a deliberate 1x raster) is honoured, as it is for Godot's own controls. The snapshot's `oversampling` is the scale the root last drew at.

**An owner that wants a high-DPI window sets one of these; the library does not.** A native window with no stretch settings has a content scale factor of 1: logical pixels are physical pixels, the text is as sharp as the screen, and the UI is small on a Retina display (the demo's 1120 x 800 window is 560 x 400 points on a 2x Mac, `DisplayServer.screen_get_scale()` is 2). To lay the UI out in points and draw it at the display's resolution, set `Window.contentScaleFactor = DisplayServer.screenGetScale()` (what the Web demo owner does every frame, so browser zoom and display changes are followed), or use the project's `display/window/stretch/mode = canvas_items`; either gives the viewport an oversampling of the scale. Injected input (`Input.parseInputEvent`) is in window pixels, which the window divides by the content scale, so a verifier gives it positions in logical pixels times the scale. A root inside a `SubViewport` has the viewport's own scale, not the window's: to render a `SubViewport` (a world-space panel) at more texels than layout pixels, set its `size2DOverride` to the layout size, `size2DOverrideStretch` on, and `size` to the texel size (`docs/WORLD_SPACE.md`).

## Styles

This is a strict, typed **Tailwind-like subset**, not Tailwind's CSS compiler or a browser stylesheet engine. `compileStyle` turns a class string and inline style into ordered, interned, frozen layers once per distinct input; native resolves which layers apply (breakpoint, hover, active, focus, disabled) and inherits `color`, `fontSize`, `textAlign`, `interpolateSize`, `pointerEvents`, `cursor`, `userSelect`, `selectionColor`, `caretColor`, `placeholderColor` and `scrollbarColor`. Unknown classes and variants throw, even if the variant is currently inactive. Matching classes apply left to right; inline styles apply afterwards. `style` accepts an object or nested arrays containing objects, `false`, `null`, and `undefined`. `StyleSheet.create` freezes reusable definitions; it does not register native style IDs.

| Variants | `sm:` 640, `md:` 768, `lg:` 1024, `xl:` 1280, `2xl:` 1536; `hover:`, `active:`, `focus:` (the focused element only), `focus-visible:`, `focus-within:` (the focused element and its ancestors), `disabled:`; combinations such as `md:hover:bg-indigo-100` |

**Filters and frosted glass.** `filter` applies CSS filter functions to an element and everything painted inside it (`blur`, `brightness`, `contrast`, `grayscale`, `hue-rotate`, `invert`, `opacity`, `saturate`, `sepia`, and one `drop-shadow`); `backdropFilter` applies them to what is already drawn behind the element, inside its rounded border box, which is frosted glass: React siblings, the main layer under a `Portal` scrim, and Godot content behind the root, 2D and 3D. Both are built from engine primitives (a copy of the render target and a mip-reading material for the backdrop, a canvas group for the filter), on the Compatibility renderer (the default, and the Web), and on the Mobile and Forward+ renderers, each measured on its own (Forward+'s back-buffer chain is a different, wider filter than the other two's, and the two RenderingDevice renderers place a level's texels by the whole target, not the copy region); any other rendering method draws nothing and logs one error. `blur(r)` is a Gaussian of standard deviation `r` logical pixels, scaled to the render target; on a hard edge the verifier holds its profile within 0.02 of a true Gaussian's and its width within the larger of 4 % and 0.6 px (the model predicts under 0.01). Separate Tailwind utilities compose across variants, so `blur-sm hover:brightness-110` keeps the blur on hover and `hover:backdrop-blur-lg` changes only material parameters, with no React work, commit, layout or re-record; an inline `filter` replaces the whole list. Both transition (`transition: { properties: ['filter', 'backdropFilter'], ... }`), function by function. An element without a filter, and a tree without any, create no item, material or shader. A frosted panel or filtered element costs roughly 0.5 to 2 ms per frame on an Apple M1 Max at 1120 x 800, nearly flat in size and radius (measured on Compatibility and Mobile; Forward+ cost was not measured; `docs/tracks/filters.md`, "Cost"), and the first use of each shader compiles it (about 50 ms on Compatibility; 0.8 to 1 s on Mobile with a cold shader cache, 17 to 36 ms with the engine's disk cache). Nothing warms the shaders up automatically, so a loading screen may show a 1 x 1 `backdrop-blur-sm` element (and a 1 x 1 `blur-sm` one for `filter`) to pay that early. Limits: an element can have both `filter` and `backdropFilter` (`backdrop-blur-xl drop-shadow-lg`): its backdrop is drawn beside its group, not in it, so unlike CSS the filter does not apply to the backdrop's result (a drop shadow is cast by the element's own fill, not by the frosted area, and shows through a translucent fill); on Compatibility and Web a group's buffer is the opaque render target's RGB10_A2 back buffer, so alpha inside a filter group has four levels (a half-transparent filtered element is drawn at a third or two thirds); a `filter` inside a `filter`, or a `backdropFilter` inside a `filter`, is reported once with an `ERROR` and not drawn (Godot's canvas groups do not nest); the colour functions of a list are composed into one matrix after the blur, so values that leave 0 to 1 between two functions are not clamped between them as a browser does; a list has at most one `drop-shadow()` and no `blur()` after it, and `backdropFilter` has none; `backdrop-filter: opacity()` blends with the unfiltered backdrop, not with the page; a blur is capped by the render target's mip levels on Compatibility (a 600 x 900 window reaches about 50 px, a 1120 x 800 one 64 px and more; the snapshot's `effects` plan says what was drawn and `clamped` when less), and on the RenderingDevice renderers a target that does not halve exactly (600 x 900, 1366 x 768) makes the last steps up to 4 to 5 % wider at 600 wide; `url()` filters, `em`/`rem` lengths and `position: fixed` descendants of a filtered element (they paint in the root, outside its group) are not supported; an ancestor's clip keeps its own pixels, so content beyond the clip is absent from the blurred picture and fades at the clip edge; a root in a `SubViewport` sees only that viewport's contents; a rotated or unevenly scaled root blurs by its mean scale; a blur near the render target's edge reads the edge texels again where a browser blurs the part beyond the window (let a blurred background bleed past the window instead of ending at its edge); a drag ghost shows a filtered source unfiltered; a scrolled `TextInput`'s own text overflow is not in its filter group's extent; a render target with a transparent background (a `SubViewport` with `transparent_bg`) has not been measured, so frosted panels over one are not claimed to work.

The palette is all 22 Tailwind v3 colours, shades 50–950, plus white, black, and transparent, as sRGB hex values; any of them takes an opacity modifier (`bg-white/20`, `bg-sky-500/30`). A frosted-glass page as a developer would write it (`backdrop-blur-xl backdrop-saturate-150 bg-white/20 border border-white/30`) is the demo's `glass` lab (`demo/src/glass-lab.tsx`), and `docs/tracks/filters.md` ("Glass showcase") compares it with the same CSS in Chrome and lists what Tailwind has that this does not (box shadows, font weights, line heights, gradients). Breakpoints use the surface's logical width, not physical display pixels. [Style types](src/types.ts), the [native protocol](native/PROTOCOL.md), [motion architecture](docs/MOTION_ARCHITECTURE.md), and the [Blitz/Stylo evaluation](docs/BLITZ_EVALUATION.md) document the supported surface and boundaries.

## Architecture and performance boundary

React 19.2.0 matches the backend's version; `react-reconciler` 0.33.0 is pinned to its compatible peer contract. React is a peer dependency so the application and renderer share one instance. Native dependencies are `godot` 0.5.5, Taffy 0.15.0 (git revision `fca167c`), and `blitz-dom` 0.3.0-beta.4 (git revision `3f85506`, retaining Stylo 0.23.0 for CSS transition resolution), locked by Cargo. Bindings use the exact API exported from the project's Godot 4.8 binary, recorded in [native/api](native/api/README.md), for both native and Web builds.

The architecture is React Native Fabric's, end to end (`docs/INTERACTION_PLAN.md`). The reconciler runs in persistent mode: during render it creates and clones lightweight, immutable JavaScript instances that share unchanged children, and it makes no native call, so abandoned concurrent renders cost nothing natively. At commit, a pure walk (`src/commit.ts`) finds the changed nodes by instance identity (an instance identical to its committed one skips its whole subtree) and sends **one `commit(layer, payload)` call** carrying only the created nodes, the prop diffs and the changed child lists. Native validates the whole payload before changing anything, diffs each changed child list (longest increasing subsequence for moves) into a mounting transaction, applies it to a mounted tree keyed by `u32` tags that JS allocates, resolves computed styles for the nodes whose inputs changed, lays out with Taffy's retained tree, updates geometry only where it changed, and re-records only the canvas items whose visuals changed. Event closures stay in JS, while native input queues are drained outside mutable Rust calls. The persistent shadow tree lives in JS rather than behind native handles because GodotJS cannot make V8 account for native memory behind wrappers (decision D2 in the plan).

Taffy owns Flexbox/Grid geometry. Godot `TextParagraph` owns text shaping and intrinsic measurement. Stylo (via `blitz-dom`) owns transition timing, easing, interruption, and reversal on the native process clock, while a dedicated native measurement tree supplies intrinsic endpoints when `interpolateSize: 'allow-keywords'` is active. A single custom `Control` owns a retained hierarchy of lightweight `RenderingServer` `CanvasItem` RIDs that mirrors the view tree (a box item and a clipping content item per element), with rectangular clipping (`overflow: 'hidden'`) for both rendering and hit testing; there is no Godot `Container` or `Control` for every React element. Moving an element changes one transform, an opacity change one modulate, and only an element whose own visuals or size changed re-records. Paint and layout invalidation are separate. Snapshots and opt-in profiles expose node geometry, computed styles, active transitions, commit counters (`nodesCreated`, `nodesUpdated`, `mutations`, `boxRecords`, `contentRecords`), and commit, layout, paint, and stage timing counters.

Measured on Chrome 156 (debug template, development React, a heavily swapped Mac; `node scripts/verify-motion-web.mjs --acceptance`, figures in `docs/INTERACTION_PROGRESS.md`, Phase F4): changing one cell's colour costs the native `commit` 0.17 to 0.20 ms at 50 and at 2,000 cells (the previous renderer: 0.79 ms and 11.7 ms), with one mutation and a 216-character payload at both sizes. Hovering and resizing across a breakpoint cause no React commit and no commit call; a 200-move hover sweep over 2,000 cells re-records two boxes per move. Updating all 2,000 cells takes about 52 ms (previously 57 ms of reconcile plus draw) and an idle frame records nothing. React still walks a parent's children when one child changes, so one change under a flat parent of 2,000 siblings costs 18 ms of JavaScript (4 ms with memoized cells) against 1.8 ms when the same cells are grouped in rows of 50; group large lists.

This remains a performance prototype: the commit payload is one JSON string per commit, a parent of many siblings is still copied by React when one child changes, intrinsic-size transitions clone the Taffy tree to measure an endpoint, and Taffy rounds its whole layout after each layout pass. It does not claim zero allocation or a frame-rate guarantee. Custom GodotJS/V8 hooks are intentionally deferred until measurements identify a bridge bottleneck; GodotJS already supplies the scheduler and ClassDB facilities required here.

a cancelable event, synchronous dispatch, enter/leave chains and three re-entrant handlers, records the JS time inside one synchronous dispatch, and runs the keyboard lab (Tab order across a reorder, the ring and `focus-visible:` for keyboard focus only, DOM key events and repeats, Enter and Space activation without pointer events, a JS focus trap, `autoFocus`, `focus()`), the pass-through HUD (presses, keys and wheel ticks reach the game exactly when React did not use them, cursors reach the window, `viewportX`/`viewportY` are canvas coordinates), the pointer lab (every mouse button, click counts, a knob that follows a captured drag outside the root, touch taps with the engine's emulation on, two fingers, a cancelled touch, and the root leaving the tree mid-press) and the scroll lab The selection lab adds click, double and triple click, drags across paragraphs past a `select-none` sentence (forwards, backwards and past the end), Shift+click, a Button, captured and prevented presses, copy to the clipboard and select all through the real `ui_copy` and `ui_text_select_all` actions, clearing by a text change or a removal, the highlight's pixels (default and custom colour, under the text, redrawn and cleared) and the highlight scrolling with, and clipped by, its list. Inspect the actual PNGs alongside the assertions.

`verify:text-layout` needs a probe build of the extension (`pnpm build:native --probe`; run `pnpm build:native` afterwards to put the default back).

Options. `pnpm verify`, `verify:motion` and `verify:interaction` are `scripts/verify.mjs`: `--only=<section>[,<section>]` runs those sections of the interaction verifier, and `verify.mjs` rejects an unknown name before it builds or launches anything. The default sections are `events`, `cooperation`, `pointers`, `keyboard`, `positioning`, `inputs`, `scroll`, `selection`, `drag`, `forms`, `hidpi`, `filters` and `glass`; `filters-sizes`, `filters-cost` (GPU cost) and `filters-faults` (negative controls) run only when named; they are not counted as left out, so a plain run is not partial. `verify:interaction:web` takes `--only=` with `events`, `cooperation`, `pointers`, `keyboard`, `scroll`, `selection`, `drag`, `forms`, `hidpi`, `filters`, `glass` and `touch`; an unknown name is an error there too. `--renderer=gl_compatibility|mobile|forward_plus` runs the windows on that Godot rendering method (the project's own is Compatibility; the evidence goes to a directory suffixed with the renderer). `--viewport=WxH` runs one window whose render target is that size, whatever the window's. `--faults` is only for `--only=filters-faults` and needs the library `pnpm build:native --faults` makes (a default run refuses it, and a faults run refuses a default build). `--no-retry` runs each window once. `verify:text-layout --headless` runs no pixel checks; `verify-motion-web.mjs` takes `--quick`, `--baseline` and `--acceptance`. Every script with options rejects an argument it does not take before it does any work (`scripts/arguments.mjs`); `verify:world` and `verify:a11y` take `--no-retry`. `pnpm demo` is the exception: it forwards its arguments to Godot. `--release` selects the release Web template; `--engine=stock` is on every script. The Web verifiers need Chrome (`CHROME` names its path).

For the browser target, see [Web build instructions](docs/WEB.md):

```sh
pnpm build:web
pnpm verify:web
pnpm verify:motion:web
pnpm verify:interaction:web
node scripts/verify-world-web.mjs   # the world-space page; it has no package script
```

The Web verifiers serve the export themselves, on a free port that only they know, and stop the server when they finish: run them with no server and no port. `pnpm demo:web` is only for looking at the export by hand (port 8096, or `PORT`). `GODOT_REACT_WEB_URL` names a server you started: the verifier then fetches every file of the export's receipt from it and refuses to open a browser unless each is byte for byte the export it checked (another checkout's, the other engine's, an older side module under the same pack all fail). Web uses the browser's JS runtime through GodotJS and the Rust extension compiled to a Wasm side module. It requires the matching threaded GodotJS templates and Emscripten/lazy-table ABI described in that guide, plus its separately pinned Rust nightly.

Where each phase's verifiers, counts and captures were recorded is `docs/INTERACTION_PROGRESS.md` (one section per phase and per track); the results of the full regression run for final acceptance go in its "Final acceptance" section. Web verification is real Chrome through Puppeteer, at device pixel ratio 1 and 2, in landscape and portrait, with a touch page, against the debug template of Breaka's engine; the `stock` profile also ran its debug and release templates. Safari, mobile devices and the release Web preset on Breaka's engine have not been qualified.

When Godot's Web shell (`fetchWithProgress`) finishes reading `index.pck` through `ReadableStream.getReader()`, Chromium can emit a benign `net::ERR_ABORTED` on the completed stream close after all `Content-Length` bytes are delivered; `verify-motion-web.mjs` verifies the exact byte count and SHA-256 of `index.pck` before allowing that post-completion event. The verifier also records the existing Emscripten dynamic-loader synchronization warning once before startup and treats all other runtime errors as failures.

## Current limits

This is the plan's non-goals (`docs/INTERACTION_PLAN.md`, 2.3) plus everything the decision log and the track notes record as not done, not fixed or not verified, each checked against the code at final acceptance. Anything not listed here is built. Details: [native/PROTOCOL.md](native/PROTOCOL.md), [docs/WORLD_SPACE.md](docs/WORLD_SPACE.md), [docs/tracks/](docs/tracks/).

**Not built, on purpose (the plan's non-goals).**

- A JSI-style binding that bypasses GodotJS's method marshalling (revisit only if measurements show the GDExtension call boundary is the bottleneck).
- A Godot `Control` per element, including `LineEdit` and `TextEdit`; a custom engine module (a proven Web engine bug is fixed in the engine's `platform/web`, not by an export-time patch).
- Drag and drop with other Godot `Control`s (`_can_drop_data` is synchronous on `&self`, where a JS answer cannot be had; `endedOutsideRoot` plus the release point is what a game uses).
- Raw text outside `<Text>`, rich or nested text runs, `contenteditable`.
- CSS stacking contexts: `zIndex` orders the siblings of one paint parent, as in React Native.
- Touch text-selection handles, long-press menus, native context menus, spellcheck.
- Animated programmatic scrolling, overscroll bounce, `position: sticky`, transforms, rounded clip masks (clipping is rectangular; border radius changes paint, not the clip), native list virtualization.
- Pen-specific pointer data: a pen is reported as a mouse.

**Not built, recorded.**

- *Styles.* There is no DOM, full CSS cascade, selector engine or Tailwind plugin support; this is a strict subset and the compiler throws on what it does not know. Rejected utilities include `shadow-*`; `font-*`, `italic`, `underline`, `uppercase`, `truncate`, `leading-*`, `tracking-*`, `whitespace-*`; `bg-gradient-*`; `border-b`, `border-t` and `border-x`; `ring-*`; `ml-auto` and `mx-auto`; `transition`, `duration-*` and `ease-*` (a transition is the inline `transition` style); `scale-*`, `translate-*`, `rotate-*`; `sticky`; `space-*` and `divide-*`; `aspect-*` and `object-*`; `col-span-*`, `row-span-*` and `grid-rows-*`; `order-*`; `h-screen`, `w-screen` and `size-*`; `w-fit` and `h-fit`; `rounded-t-*`; `invisible`, `block` and `inline`; `outline`; and the variants `dark:`, `group-*:`, `peer-*:`, `first:`, `odd:`, `before:`, `print:` and `motion-reduce:`. Grid exposes equal fractional column counts, not Taffy's track-placement API. Both overflow axes clip together (`hidden`, `scroll` or `auto` on either clips the padding box). No images, no general `@keyframes` animations or animation callbacks, no custom materials. Mixed pixel and percentage transitions, and intrinsic transitions on a flex main axis whose `flexGrow` and `flexShrink` are not zero, are rejected when the commit is validated; a style change native itself causes (a hover, a breakpoint) that would need one is applied without animation and logs an `ERROR`.
- *Scrolling.* Scrollbar track clicks (paging), pull to refresh, snap points. A wheel or pan gesture chains from one container to the next event by event, with no latching.
- *Select.* Radix's press-drag-release, item groups and separators, `position="item-aligned"`; moving the pointer over an item cut by the list's edge focuses it and scrolls it into view (`focus()` has no `preventScroll`).
- *Text selection.* Word-granularity dragging after a double click (in a `TextInput` it exists), caret affinity at wraps and direction changes, highlighting a selected line break, auto-scroll while selecting.
- *TextInput.* Native IME has not been checked by hand with a macOS Japanese or Pinyin input source (the Web IME was driven through Chrome's CDP). Engine behaviour that stays: the engine's IME start drops the last queued raw key; after a Web composition ended by a focus move `ime_started` stays set and raw keys are dropped until one more composition commits (an engine bug, to be fixed in the engine); the Right presses of two keys in one frame add up, so a text typed in a hurry into the middle of a field leaves the native caret too far right, and the caret after JS puts an edit back mid-text is off until the next key. A click inside a composing input cancels the composition without committing it. `clipboard_get` on Web returns what the previous call read, so anything else that calls it is still stale (the root's own paste no longer does). The IME window and the on-screen keyboard are placed from the root's own screen transform, which is wrong for a root on a quad in a `SubViewport`. `multiline` cannot change after creation. A triple click selects all of a text area's text, not a line.
- *Drag and drop.* Files and `setDragImage`. The ghost of a filtered source is unfiltered, and it does not follow a change of display scale mid-drag.
- *Accessibility.* `aria-labelledby`, `aria-describedby`, `aria-controls`, `aria-haspopup`, `aria-pressed` and `aria-invalid` are not typed or sent; tooltip text and its action; list and tree item counts and positions; a numeric step; `aria-live` is sent but untested. Each scroll re-sets every exposed descendant while a screen reader is attached, instead of moving one content element as `ItemList` does. The engine cannot convey a group or radio-group element, a mixed checkbox, a text area's value, a read-only field, or a scroll view's position and actions to the macOS adapter (recorded as `GODOT_REACT_A11Y_GAP`; scroll bar elements carry the position).
- *Display scale.* `CanvasItem.oversampling_with_scale` (a root whose own `scale` is above 1 draws at the viewport's level). Glyph caches at levels no viewport owns are not freed: about 20 MiB after drawing at levels 1, 2 and 3 (in use there are two sets, bounded, freed with the font). Layout and borders round to whole logical pixels.
- *World space.* No occlusion test, one quad per owner, back faces take no input, pan and magnify gestures, joypad and `ui_*` focus navigation are not forwarded, the cursor shape is not applied, hover is not re-tested when the quad or camera moves without the mouse, and the anchored label is not clamped to the window (`docs/WORLD_SPACE.md`).
- *Engine behaviours not worked around.* A trackpad pan gesture reaches Godot's `Input` twice, so JS gets two `wheel` events for one pan (and Godot's own `ScrollContainer` scrolls twice); Godot's Web display server maps a DOM `deltaX > 0` to `WHEEL_LEFT`, so horizontal wheel ticks have the opposite sign on Web; on Web a touch's `pointerId` is the browser's contact identifier, which keeps counting across taps, not `2 + index`; GodotJS's V8 has no `Intl`, so libraries that need it need a polyfill natively.
- *Platforms.* The native addon manifest targets Apple Silicon macOS only; other platforms need manifest and build work and runtime qualification.
- *Builds.* The freshness guard does not cover the Rust and Emscripten toolchains beyond `rust-toolchain.toml`, the engine, the compiled JavaScript or the tracked `demo/typings`.

**Not verified** (built, but not shown to work in the way a user would meet it).

- Native IME and VoiceOver by hand; platform focus (the verifier's window is not the key window, so the accessibility run skips it); the actions on a text field through a real adapter (the dump tool performs none).
- The platform accessibility tree on Breaka's engine, which has no accessibility driver: `pnpm verify:a11y` runs the Godot-side half there and ends "not verified" (exit 2). The macOS tree was read on the `stock` profile only. Windows (UI Automation) and Linux (AT-SPI) trees were not read, a reversed scroll axis and `scrollbar-width: none` were not read in the real tree, and the Web engine has no accessibility code.
- The kit controls, positioning and the Portal have no Web verifier section of their own (the Web interaction verifier has none for `inputs` or `positioning`), so touch on the kit `Slider` and `Select` was not exercised by a verifier. The world-space anchored label is verified natively only. IME and on-screen keyboards through a `SubViewport`, and a `SubViewport` that updates only when visible, were not exercised.
- Filters: a render target with a transparent background (a `SubViewport` with `transparent_bg`) under a frosted panel; the GPU cost on Forward+, and the cost on Web; the engine's truncation of a group's negative region, whose fix is unit-tested but did not reproduce on a real renderer.
- Whether headless Chrome reaches the system pasteboard, and the engine's own last step onto the Mac's pasteboard, because measuring writes to it (verifier runs never touch it).
- Safari, mobile devices, and the release Web preset on Breaka's engine.
- No native or Web negative controls were run for the `forms` section (five unit mutants of the `TextInput` fixes were killed), and the Web scenario that makes the soft-keyboard race deterministic is not timing-proof on a real tablet.
- The cost of hit testing (a paint-tree descent per mouse move) and of rebuilding the selection document for each gesture was not measured at scale; both are linear in the tree.
- Not done in the verifiers: an assertion count for `verify`, `verify:motion`, `verify:world` and `verify:a11y`, which are one linear script each with no section that could be left empty (the interaction and Web verifiers fail a section that made no assertion).

The prototype establishes the authoring and runtime boundary for later integration into Breaka.
